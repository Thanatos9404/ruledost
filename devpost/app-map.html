A take-home guide to where things live. Snapshot of the code after the React rebuild, 2026-10-13 (first written at slice 5, commit 624b2a2). Code can drift after this, so trust the source over this page.

What it is, in four pieces

  • Decoder src/lib/extract.js, src/lib/requirements.js: pasted text in, a "ticket" of facts out, each with a receipt.
  • Clock src/lib/time.js: reads "5:00pm EDT", finds the exact instant, shows it on your clock.
  • Judge src/lib/judge.js, src/lib/countries.js: your age and country against the eligibility facts.
  • App src/app/RuleDostApp.tsx, src/ui/TicketParts.tsx, src/ui/Receipt.tsx, src/lib/store.js: React views on the shared kit in src/kit/. They draw the ticket and save to localStorage.

The route (reference: three stops)

This is a reference route prepared from the finished code. Yashvardhan hasn't walked it hands-on yet. Open the files in an editor and use the search anchors (function names) to jump to each stop.

  1. Entry point: src/app/RuleDostApp.tsx → decodeText()

    Takes the textarea's text. Empty text gives "Paste the rules text first." Otherwise it calls decodeRules(text, { now }) and stores the ticket with setTicket(), and React re-renders the panels. If nothing was found, the paste panel shows the "doesn't look like a rules page" message with a sample button instead.

  2. Logic: src/lib/extract.js → findDeadline(), then src/lib/time.js → findDateTimes() and toUtc()

    The deadline is taken first from a "Deadline:" line, then from the end of the "Submission Period", then from a sentence with "deadline" or "due". findDateTimes() reads the date, the time and the zone wording. toUtc() turns the explicit EDT into a fixed −4 h offset (generic wording like "Eastern Time" uses the America/New_York rules instead). The receipt is the source line, with the matched span stored as mark.

    "Oct 26, 2026 @ 5:00pm EDT"  →  { y: 2026, m: 10, d: 26, hh: 17, mm: 0, zone: EDT }  →  2026-10-26T21:00:00Z
  3. Result: src/ui/TicketParts.tsx → DeadlineBlock()

    formatPieces(utc, profile.timeZone) gives "Tue, 27 Oct 2026" and "2:30 AM IST". dateShift() and isLateNight() add the two notes. ReceiptToggle and Slip in src/ui/Receipt.tsx unfold the source sentence with <mark>. React renders pasted text as text, never as HTML, because it is untrusted. useNow() re-renders the countdown every second.

A practice to reuse

Turn the acceptance criterion into a test, then check it against real data early. The PRD criterion "Oct 26, 2026 @ 5:00pm EDT shows as Tue, 27 Oct 2026, 2:30 AM IST" (devpost/prd.md → Deadline in your time zone) became the first test in tests/time.test.mjs and was then checked in the browser. The synthetic fixtures all passed, but running scripts/corpus-check.mjs over 39 real copied rules pages caught three problems they couldn't: US students marked "excluded" because of "U.S. Treasury" boilerplate, a "1-minute clip" minimum read as the video limit, and another project's MIT licence taken as the repo rule. Each fix is recorded under devpost/checklist.md → Revisions. On the next project, write the observable check first, then run it against the messiest real input you can find before trusting it.

Run it again

npm install, then npm run dev → open http://localhost:5173 (landing) or /#app · npm test for the 54 unit tests · npm run build for the static site in dist/ · npm run corpus -- <folder of copied rules .txt files> for the real-page check. Needs Node 20+ (22+ for npm test).
